# devaocubo-ds

Shared Tailwind v4 design tokens for DevAoCuboHub and its plugins.

## Contract

- `tokens.css` is the runtime CSS entrypoint. It stores HSL channel triples,
  theme selectors, and the Tailwind `@theme inline` mappings.
- `defaults.json` is the light/dark data entrypoint for generators such as
  ProjectsCLI. It uses complete CSS values and is exported as
  `devaocubo-ds/defaults.json`.
- `README.md` documents the consumer import and component recipe convention.
- The package's explicit `files` list includes `tokens.css`, `defaults.json`,
  and `README.md`.

Keep the CSS token names and JSON shape compatible with their consumers.
`tokens.css` and `defaults.json` are generated by `npm run build` in `ds/`
from `ds/packages/theme/src/legacy/devaocubo.ts`; never edit them by hand.

## Packages

The root package stays tokens-only. Components live in `ds/packages/*` as
`@gahmp1/ds-*` (`ds-theme` today; `ds-core`, `ds-native`, `ds-web`, `ds-mcp`
from wave 1 on; spec `docs/superpowers/specs/2026-10-30-componentes-devaocubo-ds-design.md`
§8). A product's identity is a theme in `ds/packages/theme/src/themes/`, never a
fork of a component. Domain components (a workout card, a transaction row) stay
in the product, not here. `ds/apps/catalog-web` (Storybook) and `ds/apps/catalog-native`
(Expo) are the visual catalogs; they are not published.

The workspace root is `ds/package.json`, never the repo root: consumers install
`devaocubo-ds` from git, and npm runs a full `npm install` of the clone when the
root `package.json` has `workspaces` or a `build`/`prepare`/`install` script
(it fails outright with `allow-scripts`). After touching the root
`package.json`, check from a temp dir:
`npm install "git+file://<repo>#$(git rev-parse HEAD)"` installs only
`tokens.css`, `defaults.json` and `README.md`.

## design-library/

`design-library/` holds the local design library: small agent skills, curated
references and HTML mockups used as visual examples. It is outside the package
`files` list, so consumers never receive it, and nothing in it is imported by an
app. Keep it text-only (no images or other binaries) so a git install stays
light. The mockups are reference material, not component implementations; the
rule above still applies to the package itself. See `design-library/README.md`
and `docs/superpowers/specs/2026-10-29-design-library-design.md`.

## Verification

Run `npm run build && npm run check` in `ds/`, then `npm test` at the root: the build regenerates the
legacy files and the theme CSS, `check` fails on any WCAG contrast pair below
its minimum, and `npm test` runs the Node test runner for `defaults.json`. Then
`git diff --exit-code tokens.css defaults.json` must stay clean. Visual changes
are verified in both catalogs (`npm run storybook -w catalog-web` in `ds/`, and
`npx expo start` in `ds/apps/catalog-native` on the iOS simulator and Android
emulator), with screenshots under each catalog's `evidence/`.
